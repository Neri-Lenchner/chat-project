# אפיון פרונט – מערכת צ'אט

## 1. מטרת המערכת

מערכת צ'אט המאפשרת למשתמשים:

- להירשם למערכת.
- להתחבר באמצעות מספר טלפון.
- לצפות ברשימת השיחות שלהם.
- ליצור שיחה חדשה.
- למחוק שיחה קיימת.
- להיכנס לשיחה ולהציג את ההודעות.
- לשלוח הודעות למשתמש אחר.
- לנהל את נתוני האפליקציה באמצעות Redux.
- לשמור את פרטי המשתמש המחובר ב־`localStorage`.

---

# 2. טכנולוגיות ועקרונות Frontend

## 2.0 Packages

ללא JavaScript בכלל! **Type Script**.

תקשורת בין בלקוח לשרת **axios**.

ה-Routing **browser router**.

לשימוש בטפסים **Hook Form**.

## 2.1 State Management

ניהול ה־State יתבצע באמצעות **Redux**.

מומלץ להשתמש ב־**Redux Toolkit**.

ה־State יחולק לשלושה אזורים עיקריים:

- `UserStore`
- `RoomStore`
- `MessageStore`

אפשר לממש אותם כ־Redux Slices:

```text
store
├── user
├── rooms
└── messages
```

---

## 2.2 עיקרון עבודה מול API

המטרה היא להימנע מקריאות API מיותרות.

לכן:

1. בכל חלק באפליקציה תתבצע קריאת API ראשונית אחת לצורך טעינת הנתונים.
2. לאחר שהנתונים נטענו, העבודה השוטפת תתבצע מול Redux בלבד.
3. פעולות שיוצרות / מעדכנות / מוחקות מידע בשרת יעדכנו גם את ה־Redux לאחר הצלחת הקריאה.
4. אין לבצע `GET` נוסף רק כדי לרענן מידע שכבר ניתן לעדכן מקומית ב־State.
5. מעבר בין מסכים לא יגרום אוטומטית לקריאה חוזרת לשרת אם המידע כבר קיים ב־Redux.

דוגמאות:

- רשימת השיחות נטענת פעם אחת ונשמרת ב־`RoomStore`.
- לאחר מחיקת שיחה, השיחה תוסר מה־`RoomStore` ללא קריאה נוספת לקבלת כל השיחות.
- לאחר יצירת שיחה, החדר החדש יתווסף ל־`RoomStore`.
- הודעות של חדר ייטענו פעם אחת וישמרו ב־`MessageStore`.
- לאחר שליחת הודעה, ההודעה שחזרה מהשרת תתווסף ל־`MessageStore`.

# 3. מבנה Redux

## 3.1 UserStore

אחראי על המשתמש המחובר.

### State מוצע

```ts
type UserState = {
  user: User | null;
  isLoading: boolean;
  error: string | null;
};
```

### אחריות

- שמירת המשתמש לאחר הרשמה.
- שמירת המשתמש לאחר התחברות.
- טעינת המשתמש מ־`localStorage` בעת פתיחת האפליקציה.
- ניקוי המשתמש בעת Logout.
- שמירת סטטוס טעינה ושגיאות הקשורות למשתמש.

---

## 3.2 RoomStore

אחראי על רשימת השיחות.

### State מוצע

```ts
type RoomState = {
  rooms: Room[];
  isLoading: boolean;
  isLoaded: boolean;
  error: string | null;
};
```

### אחריות

- טעינת רשימת השיחות מהשרת.
- מניעת טעינה חוזרת אם הרשימה כבר נטענה.
- הוספת Room חדש ל־State.
- מחיקת Room מה־State.
- עדכון ההודעה האחרונה של Room לאחר שליחת הודעה.
- עדכון תאריך / שעה של השיחה האחרונה במידת הצורך.

---

## 3.3 MessageStore

אחראי על ההודעות של החדרים.

מומלץ לשמור הודעות לפי `roomId`.

### State מוצע

```ts
type MessageState = {
  messagesByRoom: {
    [roomId: string]: Message[];
  };

  loadedRooms: {
    [roomId: string]: boolean;
  };

  loadingByRoom: {
    [roomId: string]: boolean;
  };

  errorByRoom: {
    [roomId: string]: string | null;
  };
};
```

### אחריות

- טעינת הודעות של חדר.
- שמירת ההודעות לפי מזהה חדר.
- מניעת קריאת API נוספת לחדר שכבר נטען.
- הוספת הודעה חדשה לאחר שליחה מוצלחת.
- שמירת שגיאה נפרדת לכל חדר במידת הצורך.

---

# 4. שמירת משתמש ב־Local Storage

לאחר הרשמה או התחברות מוצלחת, יש לשמור את המשתמש גם ב־Redux וגם ב־`localStorage`.

לדוגמה:

```ts
localStorage.setItem("user", JSON.stringify(user));
```

בעת פתיחת האפליקציה:

1. יש לבדוק האם קיים משתמש ב־`localStorage`.
2. אם קיים, יש לטעון אותו ל־`UserStore`.
3. אם לא קיים, יש להפנות למסך התחברות / הרשמה.

לדוגמה:

```ts
const savedUser = localStorage.getItem("user");

if (savedUser) {
  const user = JSON.parse(savedUser);
}
```

בעת Logout:

```ts
localStorage.removeItem("user");
```

בנוסף יש לנקות את ה־Redux הרלוונטי.

```http
POST http://localhost:8000/api/user/
```

`User`

```json
{
  "firstName": "ישראל",
  "lastName": "ישראלי",
  "phone": "0501234567"
```

**Response:**

`User`

1. שמירת המשתמש ב־`UserStore`.

4. מעבר למסך הראשי.

## 7.2 שליפת רשימת השיחות

### API

**Endpoint:**

```http
GET http://localhost:8000/api/room-user/room/{user-id}
```

**Path Parameter:**

- `user-id` – מזהה המשתמש המחובר.

**Response:**

`List<Room>`

### התנהגות Redux

בעת כניסה למסך הראשי:

```text
האם RoomStore.isLoaded = true?
│
├── כן  → הצגת הנתונים מה־Redux בלבד
│
└── לא  → GET rooms → שמירה ב־Redux → isLoaded = true
```

כלומר, מעבר חוזר למסך הראשי לא יגרום לקריאה נוספת לשרת כל עוד הנתונים כבר קיימים ב־State.

- שם איש הקשר.

### הצגת תאריך

- אם ההודעה האחרונה נשלחה **היום** – יש להציג שעה בלבד.
- אם ההודעה אינה מהיום – יש להציג תאריך.

לדוגמה:

```text

```

או:


# 11. שליפת הודעות בחדר


**Path Parameter:**

- `room-id` – מזהה החדר.

# 12. שליחת הודעה

שליחת הודעה תתבצע באמצעות מזהה המשתמש השולח ומזהה המשתמש המקבל.

### API

```http
POST http://localhost:8000/api/message/user/{user-id}/other/{other-user-id}
```

**Path Parameters:**

- `user-id` – מזהה המשתמש המחובר.
- `other-user-id` – מזהה המשתמש שאליו נשלחת ההודעה.

**Request Body:**

```json
{
  "content": "שלום, מה נשמע?"
}
```

**Response:**

`Message`

### תרחיש הצלחה

לאחר קבלת ההודעה מהשרת:

1. הוספת ההודעה ל־`MessageStore` תחת ה־`roomId` המתאים.
2. עדכון ההודעה האחרונה ב־`RoomStore`.
3. עדכון זמן ההודעה האחרונה ב־`RoomStore`.
4. ניקוי שדה הטקסט.
5. הצגת ההודעה החדשה במסך.
6. גלילה להודעה האחרונה במידת הצורך.
7. אין לבצע `GET` נוסף של ההודעות.

### תרחיש שגיאה

- הצגת הודעת שגיאה.
- אין לנקות את תוכן ההודעה.
- אין להוסיף הודעה ל־State כאילו נשלחה בהצלחה.
- יש לאפשר ניסיון חוזר.

# 23. תרחיש משתמש מלא

## משתמש חדש

1. המשתמש נכנס למסך הרשמה.
2. ממלא שם פרטי, שם משפחה ומספר טלפון.
3. לוחץ על "הרשמה".
4. הפרונט שולח `POST /api/user/`.
5. לאחר הצלחה המשתמש נשמר ב־`UserStore`.
6. המשתמש נשמר ב־`localStorage`.
7. המשתמש מועבר למסך הראשי.
8. אם השיחות עדיין לא נטענו, נשלחת קריאת API לקבלת השיחות.
9. השיחות נשמרות ב־`RoomStore`.
10. המשתמש בוחר "הוספת שיחה".
11. מוצגת רשימת אנשי קשר מקומית.
12. המשתמש בוחר איש קשר.
13. נשלחת בקשה ליצירת Room.
14. החדר שחזר מהשרת נוסף ל־`RoomStore`.
15. המשתמש מועבר למסך השיחה.
16. אם הודעות החדר עדיין לא נטענו, נשלחת בקשה לקבלת הודעות.
17. ההודעות נשמרות ב־`MessageStore`.
18. המשתמש יכול לשלוח הודעות חדשות.
19. כל הודעה חדשה שחוזרת מהשרת מתווספת ל־State ללא Fetch חוזר.

## משתמש קיים

1. המשתמש נכנס למסך התחברות.
2. מזין מספר טלפון.
3. לוחץ על "התחברות".
4. הפרונט שולח `POST /api/user/login`.
5. המשתמש נשמר ב־`UserStore`.
6. המשתמש נשמר ב־`localStorage`.
7. המשתמש מועבר למסך הראשי.
8. רשימת השיחות נטענת פעם אחת.
9. המשתמש יכול להיכנס לשיחה, לשלוח הודעה או למחוק שיחה.
10. כל שינוי מוצלח מול השרת מתעדכן ישירות ב־Redux.

## משתמש שכבר מחובר

1. המשתמש פותח מחדש את האפליקציה.
2. האפליקציה קוראת את המשתמש מ־`localStorage`.
3. המשתמש נטען ל־`UserStore`.
4. המשתמש מועבר למסך הראשי.
5. נתוני השיחות וההודעות ייטענו לפי הצורך.

# 24. נקודות שדורשות השלמה מול ה־Backend

לפני מימוש מלא יש לוודא:

- המבנה המדויק של `User`.
- המבנה המדויק של `Room`.
- המבנה המדויק של `Message`.
- המבנה המדויק של Request ליצירת הודעה.
- המבנה המדויק של Request ליצירת Room.
- האם `Room` מייצג שיחה בין שני משתמשים בלבד או תומך בקבוצה.
- כיצד מתקבל `other-user-id` מתוך Room.
- האם נדרש Authentication / Token.
- מהו מבנה השגיאות שמוחזר מהשרת.
- האם קיימת מגבלה או ולידציה על מספר הטלפון.
- מהו שם השדה המדויק עבור תוכן הודעה.
- מהו שם השדה המדויק עבור שם איש הקשר.
- האם Room כולל מידע על ההודעה האחרונה.
- האם Room כולל את תאריך ההודעה האחרונה.
- האם לאחר יצירת Room השרת מחזיר את המשתמשים המשויכים לחדר.
- האם השרת מונע יצירת שני Rooms זהים בין אותם משתמשים.

# 27. כלל מרכזי למימוש

> **השרת הוא מקור המידע הראשוני, אך לאחר טעינת הנתונים Redux הוא מקור המידע של ה־UI.**

כלומר:

```text
API → Redux → UI
```

ולא:

```text
API → UI
API → UI
API → UI
```

בפעולות שינוי:

```text
UI → API → Redux → UI
```

לדוגמה:

```text
שליחת הודעה
      │
      ▼
POST /message
      │
      ▼
Message Response
      │
      ▼
MessageStore
      │
      ▼
UI מתעדכן
```

כך מצמצמים קריאות API, שומרים על State עקבי ומשפרים את מהירות וחוויית השימוש באפליקציה.
